# Контракты приложения `user_profile`

Приложение подключено как `path("profile/", include("user_profile.urls"))`, namespace - `profiles`.
Служебное приложение - своей модели нет, читает `User` (users) и `Pet` (pets).

---

## Просмотр профиля
- **URL:** /profile/<int:pk>/
- **View:** user_profile.views.profile_detail
- **Шаблон:** templates/profiles/profile_detail.html
- **Доступ:** гость читает (доступна и не авторизованным)

### Контекст
| Переменная | Тип | Описание |
| --- | --- | --- |
| profile_user | User | юзер, чей профиль открыт (display_name, avatar_url, email) |
| pets | list[Pet] | питомцы юзера; пустой список - валидное состояние |
| can_manage | bool | владелец профиля или админ - показывать кнопку "Редактировать" |

### Действия на странице
- Кнопка «Редактировать» (только если can_manage) → GET users:profile_edit
- Кнопка «Добавить питомца» → GET на страницу создания из pets (см. contracts/pets.md, когда появится)

### Ошибки
- Юзер с данным pk не найден → 404 (обрабатывает view через get_object_or_404)

### Важно
- Своей модели нет: список питомцев временно захардкожен пустым
  (`pets = []`) до появления модели Pet. После мержа pets
  заменяется на `profile_user.pet_set.all()` - контекст и шаблон
  не меняются, меняется только источник данных внутри view.
- Не путать с `users:profile_edit` - это разные приложения:
  `profile_detail` - публичный просмотр (свой/чужой, доступен гостю),
  `profile_edit` - форма редактирования только своих данных
  (login_required, без параметра pk).

# Документация в wiki: структура и правила

Главная задача wiki - **контракты view - шаблон**: автор view фиксирует, что кладёт в контекст, автор шаблона верстает по этому описанию, не читая чужой код.

---

## Структура

```text
docs/wiki/
├── Home.md                      # Навигация: ссылки на все страницы
├── Руководство_по_работе_с_проектом.md
│
├── contracts/                   # Контракты view - шаблон, один файл на приложение
│   ├── _template.md             # Шаблон блока
│   ├── users.md
│   ├── profile.md
│   ├── pets.md
│   ├── posts.md
│   ├── comments.md              
│   ├── reactions.md             
│   ├── subscriptions.md         
│   ├── feed.md
│   └── search.md
│
└── conventions/                 # Сквозные соглашения
    ├── Дизайн-система.md        # .pixel-panel, clip-path, шрифты, текстуры
    ├── Шаблоны_и_вёрстка.md     # base.html: блоки, includes
    ├── Права_доступа.md         # can_manage / can_delete
    └── Тестирование.md
```

Один файл контрактов = одно Django-приложение (зеркально декомпозиции). Внутри файла - по блоку на каждую view, которая рендерит страницу или виджет.

---

## Шаблон контракта (`contracts/_template.md`)

```markdown
## <Название страницы/виджета>
- **URL:** /pets/<int:pk>/
- **View:** pets.views.PetDetailView
- **Шаблон:** templates/pets/pet_detail.html
- **Доступ:** гость читает / login_required

### Контекст
| Переменная | Тип | Описание |
| --- | --- | --- |
| pet | Pet | name, avatar, breed, birthday, pet_type, sex |
| posts | Page | пагинатор, посты питомца, новые сверху |
| can_manage | bool | показывать владельческие кнопки |

### Действия на странице (если есть)
- Кнопка «Подписаться» - POST subscriptions:subscribe (см. contracts/subscriptions.md)

### Ошибки
- Объект не найден - 404 (обрабатывает view, не шаблон)
```

Для виджетов (`reactions`, `subscriptions`, `comments`) вместо URL/View - какие переменные include ожидает через `{% include ... with ... %}`.

---

## Правила

1. **Кто пишет:** автор view. **Когда:** в том же PR, где появилась view. Нет контракта - PR не аппрувится.
2. Сквозные соглашения (пересекают все приложения) - в `conventions/`, обновляет тот, кто вводит соглашение.
3. Новая страница wiki - ссылка в `Home.md` в том же коммите.
4. Чисто документационные изменения - отдельный PR, коммит с префиксом `docs:`.
